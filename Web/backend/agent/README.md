# SportsBuilder agent

This is a local prototype implementation. The service binds to `127.0.0.1:3001`; Vite forwards `/agent` requests. Run all local processes with `bun run dev`, or run the existing ChatGPT proxy (`bun run ai:proxy`), FastAPI, Vite, and `bun run agent` separately. Build the frontend with `bun run build` before creating a tool: Daytona reviews that built fixed app.

In development, the default provider is the local `openai-oauth@2.0.0` proxy at `127.0.0.1:10531`; production selects OpenRouter. Complete the local proxy's browser sign-in when requested. An explicit `SOL_PROVIDER` override can select either provider; OpenRouter requires `OPENROUTER_API_KEY`. Both paths use GPT-6.1 Sol with medium reasoning, identical prompts, tools, formula validation, and review policy. Provider errors are visible and never trigger an alternate paid provider. Nonsecret model, URLs, budgets, batching and sandbox policy live in `Web/backend/agent/config.ts`; environment files hold credentials.

`DAYTONA_API_KEY` and `AGENT_INTERNAL_SECRET` stay in the ignored root `.env.local`. The local runner generates a shared ephemeral internal secret if none is configured. Never send provider, database, or object-storage credentials into the sandbox. Only the static app build and tool drafts are uploaded.

The interview creates a confirmed brief. Building uses bounded model tool calls for workspace files, terminal commands, trusted calculations, and Playwright browser inspection. `.agents/learnunlock/reviewedArtifactAuthoring.ts` is the unchanged LearnUnlock production review harness: at most two private drafts and three review decisions, exact-revision acceptance, shared cancellation, and no save before inspection. The adapter validates all metrics, renders actual desktop/mobile screenshots in Daytona, returns those pixels to the model, and saves only the exact accepted config. It uploads only `Web/frontend/dist`, never host credentials, and never publishes sandbox code. Python and Playwright run in a uv-managed environment with a pinned Playwright dependency; a sandbox missing uv receives its official installer. Evidence is written under ignored `output/builds/<job-id>/`. Sandboxes auto-stop after ten minutes and are deleted after use; a failed cleanup is reported server-side.

Public entry: `index.ts` exports configuration and contracts without starting a server. Layer boundaries: `types.ts` defines conversation/job contracts; `config.ts` owns nonsecret policy; `services/provider.ts` translates the shared conversation to each provider; `runtime/sandbox.ts` owns remote process/file/browser side effects; `runtime/server.ts` owns the local API and orchestration. `server.ts` is only the process entry point. Shared measurement capabilities are imported through the public `shared` barrel.

The coach is a separate conversation. It loads actual decoded images and matching numeric measurements from FastAPI, inspects all sampled frames in chronological batches, then synthesizes a timestamped answer and optional drill using the rubric, profile, and recorded history. Missing athlete images and incomplete analyses fail explicitly. Optional reference footage is inspected separately; unavailable reference analysis is disclosed without discarding the athlete report. Up to three earlier complete sessions for the same athlete and tool supply numerical history without reloading historical images. Each session uses its own ground line, calibration, units, and target availability. The coach must not infer improvement from incompatible camera views or uncalibrated pixel scales. Configured target ranges are rubric criteria rather than universal good-form standards. Pixel coordinates remain pixels until calibration; reference footage does not inherit the athlete's calibration. Synthetic sample motion is never sent as real coaching evidence.

Endpoints:

- `GET /agent/health`: configured provider/model and local proxy readiness.
- `POST /agent/interview`: `{messages,current?}` → `{reply,ready,brief?,preview?}`. Complete preview configurations pass formula and unit validation; invalid output receives one correction attempt. The client keeps the previous stable preview until a complete result arrives.
- `POST /agent/build`: `{brief?,candidate?,messages,referenceId?,save?}` → `{id}`. A validated candidate avoids redundant drafting turns. `save:false` reviews without saving; omission preserves the original automatic-save API. Local preview publication precedes remote environment preparation.
- `POST /agent/jobs/:id/save`: saves the server-held accepted configuration only after that build completes. Concurrent/repeated saves share one write; caller-supplied configurations are not accepted here. Refinements create a new record and preserve existing recordings' tools.
- `POST /agent/coach`: `{sessionId,tool,messages,selectedTime,calibration?}` → `{id}`.
- `GET /agent/jobs/:id`: `{status,stage,preview?,previewRevision?,timings?,tool?,reply?,drill?,error?}`. Preview is a math-checked sample configuration, not permission to use it on athlete footage. Completion of a build establishes screenshot acceptance; saving remains separate when requested.

Jobs are held in memory for this single local process. Restarting the agent invalidates pending jobs; the client must retry. No deployment, production load guarantee, or live pose-estimation accuracy is established by a successful synthetic browser review. Railway hosting requires separately configured secrets, processes, storage, networking, and resource limits; none is deployed by this implementation.
